# research-sweep — per-source query patterns

Run the relevant subset for the topic. Not every topic needs every source.

## Web search

- Start broad, then narrow with the specific terms the first results surface.
- Add a year anchor for anything time-sensitive (the search hook may do this for
  you; if not, add it yourself).
- Pull the actual page bodies for the 3-5 most relevant hits, not just snippets.

## Discussion / forums

- Query the topic plus the platform's signal words ("vs", "experience with",
  "problems with") to find lived experience rather than marketing.
- Read the comment bodies, not just the post titles — the disagreement in the
  replies is usually the most useful part.

## Primary sources

- For a tool or library: the docs, the changelog, and the issue tracker.
- For a claim about a paper: the paper itself, not a summary of it.

## What to record per source

For each useful hit: the URL, one line on what it actually says, and whether it
agrees or disagrees with the other sources. That record is the input to the
synthesis pass.
